# Embodied Research Radar — Agent Instructions

> This file is auto-loaded by AtomCode at every session start.

## Before Every Task

Unless the user explicitly skips:

1. Read `docs/PROJECT_CONTEXT.md`
2. Read the top section of `docs/ITERATION_LOG.md` (recent 5 entries)
3. Run `git status` and `git log -5 --oneline`
4. Read only source files directly relevant to the current task
5. If the task involves workflow, schema, research logic, deployment, or data pipeline — also read the PROJECT_CONTEXT section for that topic and the actual source file

**If PROJECT_CONTEXT conflicts with current code, the code is authoritative. Fix the docs at task end.**

Full task workflow details: `docs/TASK_WORKFLOW.md`

## After Every Task

1. If the task changed Architecture, Data Flow, Schema, Workflow, CLI, Research Logic, or Production Behavior → update the relevant section of `docs/PROJECT_CONTEXT.md`
2. Append an entry to the top of `docs/ITERATION_LOG.md` (schema in that file's header)
3. Tiny changes (typo, 2-3px CSS) can be merged into a same-day "UI Polish" entry

## Critical Safety Rules

- **Never force push** unless the user explicitly requests and confirms the risk
- **Protect remote paper IDs**: when merging `data/papers.json`, `remote_paper_ids ⊆ final_paper_ids` must hold
- **"Radar found nothing" ≠ "nobody studied it"** — never equate search coverage with academic reality
- **Research Gap changes** must consider: Supporting, Counter, Coverage, Claim Version, Evidence Freshness
- **No backend** — this is a static GitHub Pages site
- **No secrets in repo** — API keys/tokens via environment variables only
